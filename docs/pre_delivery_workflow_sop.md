# 嘉定买房决策参谋系统：交付前自动化全量验证工作流标准作业程序 (Pre-Delivery Workflow SOP)

> **版本**：V1.0  
> **生效时间**：2026-09-18  
> **执行原则**：**自动化断言优先，红线零容忍，无全绿测试绝不交付**。

---

## 1. 制定背景与历史痛点溯源

在软件开发与迭代过程中，随着功能复杂度提升，容易发生因局部修改导致历史核心功能意外倒退（Regression，回归退化）的情况。为彻底杜绝此类质量隐患，必须将开发交互过程中暴露出的所有典型问题固化为自动化测试用例，并建立统一的交付前门禁工作流（Pre-Delivery Workflow）。

### 历史核心缺陷排查与对齐清单
1. **安全口令泄露隐患**：
   - *历史问题*：早期版本口令明文硬编码于前端 JavaScript（脚本语言）源码中，且口令不合规；
   - *门禁标准*：必须严格锁定安全口令为 `9802`，并在前端使用单向加盐的 SHA-256（安全散列算法）哈希校验，禁止任何明文口令出现在客户端代码中。
2. **多维表格滚动交叉标头脱节**：
   - *历史问题*：多维表格横向滚动时，第1列（小区名）与第2列（得分）数据单元格冻结，但表头未设置正确的双向粘性定位（Sticky Positioning），导致表头错位与内容遮挡；
   - *门禁标准*：表头交叉区域必须赋予最高图层级别（`z-index: 38 !important`），具备实心背景与立体阴影，横向滚动 600 像素以上时依然绝对锁定。
3. **双栏分屏交互重叠遮挡**：
   - *历史问题*：在左图右表双栏联动模式下，单击表格行强行滑出右侧大抽屉，导致多维表格被完全盖死；
   - *门禁标准*：双栏模式下单击仅触发地图高亮与平滑飞渡；仅当双击或主动点击【全景档案】时，以居中悬浮模态工作台（880像素宽）形式呈现，彻底杜绝侧边抽屉覆盖。
4. **户型图与物理房间数错配（保利湖畔阳光苑痛点）**：
   - *历史问题*：人工维护数据时缺乏物理校验，保利阳光苑的三房错误引用了仅有两间卧室的图片；
   - *门禁标准*：建立《户型图权威真值元数据库》，所有图片必须经过 OCR（光学字符识别）实测物理房间数标定，两房必须有且仅有 2 间卧室，三房必须有 3 间卧室（主卧、次卧、书房/客卧），并在构建期设置硬断言，两房与三房图片哈希绝对不可相同。
5. **立体交通噪音评估失真（中信泰富大盘痛点）**：
   - *历史问题*：早期只评估直线地铁站距离，忽略了地上轻轨高架（11号线嘉定新城至白银路段）、胜辛路双向8车道主干道及高架引桥的双重立体受噪；
   - *门禁标准*：引入空间矢量几何拓扑引擎，精准计算空间垂距，中信泰富全系必须识别出 11 号线高架（48米）与胜辛路（0米）双重受噪，并注入现场避坑指南。
6. **全景工作台键盘连续对比**：
   - *历史问题*：用户查看详情时频繁需要对比下一个小区，每次都必须退出重选；
   - *门禁标准*：居中工作台原生支持键盘 `ArrowLeft`（左箭头）与 `ArrowRight`（右箭头）环形无缝翻页，且当搜索过滤为单项时自动退化为全量轮询，按 `ESC` 键平滑退出。
7. **全屏 1440P 原图 Lightbox（灯箱放大）体验**：
   - *门禁标准*：户型图支持点击后在最高图层（`z-index: 9999`）全屏展示无损高清原图，点击遮罩或按 `ESC` 退出。
8. **高架/轨交噪音一票否决权**：
   - *门禁标准*：开启开关后，距离高架或主干道小于 80 米且无天然声屏障的房源，必须被精准高亮标记降权，保障买房人决策安全。

## 2. 自动化质量门禁流水线架构

系统提供一键执行的端到端自动化质量流水线：
```bash
bash scripts/run_delivery_workflow.sh
```

整个流水线由 5 大串联步骤构成，严格执行 Linux 脚本的 `set -e` 熔断机制：

```mermaid
flowchart TD
    A["启动流水线 (scripts/run_delivery_workflow.sh)"] --> B["[步骤 1] 户型图真值元数据库生成 (build_floorplan_catalog.py)"]
    B -->|通过| C["[步骤 2] 78 套户型物理房间数断言 (refine_layouts_data.py)"]
    C -->|通过| D["[步骤 3] 多源立体交通噪音几何拓扑计算 (spatial_noise_engine.py)"]
    D -->|通过| E["[步骤 4] 零依赖离线数据集打包编译 (build_dataset.py)"]
    E -->|通过| F["[步骤 5] 交付前全量质量门禁与端到端回归测试 (verify_all_regression.py)"]
    F -->|全部通过 (耗时约14秒)| G["🎉 签发可信交付状态 (Ready for Delivery)"]
    
    B -.->|异常报错| X["❌ 立即熔断中断交付"]
    C -.->|异常报错| X
    D -.->|异常报错| X
    E -.->|异常报错| X
    F -.->|断言失败| X
```

### 各步骤职责与产物说明

| 步骤编号 | 执行脚本 | 职责与校验内容 | 核心输出产物 |
| :--- | :--- | :--- | :--- |
| **步骤 1** | `build_floorplan_catalog.py` | 扫描本地高清户型图资源，依据 OCR 物理房间标尺构建权威真值特征库 | `data/floorplan_catalog.json` |
| **步骤 2** | `refine_layouts_data.py` | 将 35 个小区 78 套户型档案与真值库对齐，执行房间数数学断言 | `data/jiading_xiaoqu.json` |
| **步骤 3** | `spatial_noise_engine.py` | 载入 11 号线地上高架段、胜辛路主干道、S5 高速空间拓扑折线计算垂距与声屏障衰减 | 注入多源立体交通噪音评估报告 |
| **步骤 4** | `build_dataset.py` | 将结构化 JSON 编译为免跨域、零依赖的全局只读 JavaScript 数据包 | `data/dataset.js` |
| **步骤 5** | `verify_all_regression.py` | 静态数据代码安全检验 + Playwright 无头浏览器端到端 9 大全场景回归测试 | 终端通过仪表盘报告 (Exit Code 0) |

## 3. 测试集用例与断言矩阵 (Regression Suite)

全量回归测试脚本包含两个核心阶段：

### 阶段一：静态数据真值与代码安全性核验
- **检查项 1（代码安全性）**：扫描 [index.html](file:///Users/wentao.hu/Documents/HomePage/00-projects/00-doing/买房参考软件/index.html)，断言绝对不得包含任何明文密码字符串，门禁校验仅允许使用 SHA-256 加盐哈希；
- **检查项 2（数据完整性）**：扫描 [data/jiading_xiaoqu.json](file:///Users/wentao.hu/Documents/HomePage/00-projects/00-doing/买房参考软件/data/jiading_xiaoqu.json)，断言全量 35 个小区的坐标、年份、绿化率及 2026 中考统考市重点率对口初中完整存在；
- **检查项 3（户型真值核验）**：断言 78 套户型名称中的“两房/三房”与图片中的物理房间数 100% 严格一致，严禁保利阳光苑等两房三房串图；
- **检查项 4（多源噪音拓扑核验）**：断言中信泰富一二三期的数据中同时包含 `11号线地上轻轨高架`、`胜辛路双向8车道主干道` 以及实勘避坑指南。

### 阶段二：Playwright 端到端全场景浏览器自动化测试
- **场景 1（安全门禁解锁流）**：模拟用户输入正确口令 `9802`，回车解锁，校验门禁遮罩淡出，错误口令触发抖动；
- **场景 2（双栏联动防遮挡）**：在双栏模式下单击任意表格行，校验仅触发高亮与飞渡，绝不弹出抽屉覆盖多维表格；
- **场景 3（多维表格双向冻结）**：横向滚动多维表格 600px，验证小区名称列与综合得分列始终吸顶吸左，CSS `z-index >= 35`，立体阴影完整呈现；
- **场景 4（居中工作台与保利户型实证）**：双击或点击【全景档案】弹出 880px 居中工作台，验证保利湖畔阳光苑两房（2卧双阳台图 `107116374473.jpg`）与三房（3卧双卫图 `107116447609.jpg`）互不相同且与物理标注绝对吻合；
- **场景 5（全屏 Lightbox 原图与 ESC 退出）**：点击工作台缩略图，验证 1440P 灯箱弹窗全屏展开，按 `ESC` 键平滑退出；
- **场景 6（工作台键盘左右翻页）**：按键盘 `ArrowRight` 自动切换到下一个小区，按 `ArrowLeft` 返回上一个小区，单项过滤场景下自动全量轮询不卡死；
- **场景 7（中信泰富多源立体噪音报告）**：验证中信泰富工作台内地上高架、胜辛路主干道及实勘避坑指南展示完整；
- **场景 8（高架/轨交噪音一票否决）**：点击一票否决切换开关，断言受噪超标房源精准打上降权标记；
- **场景 9（三大高端主题无缝切换）**：通过主题切换器在【黑曜终端】、【暖调纸本】与【极客蓝图】之间切换，校验 `html` 根类名与色彩变量即时同步生效。

## 4. 交付质量红线与制度规范

为确保系统每次交付的用户体验与数据精确度，特设立以下强制性红线：

1. **红线 1：交付前必跑流水线**  
   任何功能新增、样式调整、脚本优化或数据更新结束后，**必须**在终端运行 `./scripts/run_delivery_workflow.sh`；
2. **红线 2：未全绿严禁交付**  
   若 5 大步骤中有任何一项报错或断言失败，严禁提交代码或向用户汇报完成，必须在排查修复并通过测试后方可交付；
3. **红线 3：新增功能必须补齐用例**  
   若未来引入新特性（如新增房源比价公式、新板块拓扑等），必须在 [scripts/verify_all_regression.py](file:///Users/wentao.hu/Documents/HomePage/00-projects/00-doing/买房参考软件/scripts/verify_all_regression.py) 中追加对应的断言用例，持续扩大保护伞覆盖度。
