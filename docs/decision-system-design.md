# 嘉定购房参考地图与多维决策分析系统 — 详细设计方案

## 1. 系统概述与升级目标

本项目在现有 Leaflet 地图和嘉定 35 个标杆小区/分期户型档案库的基础上，全面升级为**专业级个人购房决策与多维对比工作台**。

核心解决三大痛点：
1. **决策维度单一**：不仅看地理位置，还需要横跨房龄、交通、学区、医院、商业、环境、物业、户型、噪音、车位等 **16 大综合指标**；
2. **缺乏全景横向对比**：突破传统单一地图的展示局限，引入类似多维表格（Bitable / Notion 表格）的全屏与分屏对比能力；
3. **主观与客观评价割裂**：建立科学的可调权重打分引擎，结合客观大数据评分与用户实地看房微调，并内置“高架噪音一票否决”硬红线。

## 2. 16 大一级指标体系与数据分层设计

指标划分为三个实体层级，确保数据结构科学、不产生维度冲突：

```
                    ┌────────────────────────────┐
                    │ 实体 1：小区 / 分期大盘级   │
                    │ (宏观社区公域属性，全盘共享) │
                    └─────────────┬──────────────┘
                                  │ 包含
                                  ▼
                    ┌────────────────────────────┐
                    │ 实体 2：主力户型级         │
                    │ (标准两房/三房，全明得房率) │
                    └─────────────┬──────────────┘
                                  │ 对应
                                  ▼
                    ┌────────────────────────────┐
                    │ 实体 3：单套房源实勘级     │
                    │ (楼层/噪音微环境/看房打分) │
                    └────────────────────────────┘
```

## 4. 综合打分模型与高架噪音“一票否决”算法

### 4.1 五大核心维度与默认权重配置

为了让 16 项指标具备高度实操性，系统将指标收敛为 5 个核心评分维度：

$$\text{综合得分} = \sum_{k=1}^{5} \left( W_k \times S_k \right) - \text{否决惩罚}$$

| 维度编码 | 维度名称 | 涵盖的一级指标 | 默认权重 ($W_k$) | 权重调节范围 |
| :--- | :--- | :--- | :--- | :--- |
| **DIM_1** | **交通与市中心通勤** | ② 地铁 + ⑪ 与市中心距离 | **25%** | 0% ~ 50% |
| **DIM_2** | **优质学区与教育** | ③ 学校（以中考市重率梯队计） | **20%** | 0% ~ 50% |
| **DIM_3** | **户型空间与得房率** | ⑧ 开门动线 + ⑨ 户型得房率 | **20%** | 0% ~ 50% |
| **DIM_4** | **居住环境与静谧品质** | ⑥ 小区环境 + ⑫ 阳台景观 + ⑬ 公园 + ⑭ 噪音 + ⑮ 车位 | **20%** | 0% ~ 50% |
| **DIM_5** | **商业医疗与资产性价比**| ① 房龄 + ④ 医院 + ⑤ 商业 + ⑦ 物业 + ⑯ 均价 | **15%** | 0% ~ 50% |

> **权重自平衡机制**：用户调整任一维度的滑块，系统保持总权重为 100%，实时刷新全量小区综合分。

### 4.2 高架/高速噪音一票否决逻辑
* **触发条件**：小区与 G15嘉金高速、S26沪常高速、S5沪嘉高速或嘉闵高架的物理距离 $< 200$ 米；
* **一票否决处理机制**：
  1. 页面顶栏提供 `[🚫 开启高架噪音一票否决]` 开关；
  2. 开关开启时：触发高架噪音的小区在表格和地图中直接进入“淘汰区”（默认自动折叠隐藏，或置底灰显，综合评分强制清零）；
  3. 开关关闭时：在环境维度中做重度扣减（单项计 40 分以下），并高亮标红 `🔴 临高架严重噪音`。

## 5. 前端产品形态：三种视图模式设计

在顶栏右侧提供三模切换开关组件：

```
顶栏右侧: [ 🗺️ 纯地图模式 ]  [ ◫ 分屏联动模式 ]  [ 📊 全屏多维表格 ]  [ ⚙️ 权重配置 ]
```

### 模式 1：`[◫ 分屏联动模式]` (默认推荐)
- **左侧 45%**：Leaflet 高德真彩矢量/航拍卫星底图，保留缩放、图钉渲染、圆心吸附；
- **右侧 55%**：多维表格视图，默认展示【小区名称】、【综合得分】、【对口初中及市重率】、【地铁步行耗时】、【得房率】、【噪音状态】、【挂牌单价】；
- **双向联动**：
  - 点击表格行，左侧地图自动平滑飞渡（`flyTo`）到该小区位置，图钉弹出浮动微气泡；
  - 在地图点击任意图钉，右侧多维表格自动滚动并将该行高亮锁定。

### 模式 2：`[📊 全屏多维表格模式]` (深度横向大评比)
- 100% 满屏宽度显示，支持 16 大指标所有详细列的横向滚动；
- **冻结列**：小区名称与综合推荐得分固定在最左侧，不随滚动条位移；
- **交互列**：
  - 支持直接在单元格中点击打星（1~5星）或修改单项得分（方案 C：基准分 + 手动覆盖）；
  - 支持添加“看房实勘备注”输入框；
- **高级排序过滤**：一键按“综合得分倒序”、“得房率倒序”、“地铁距离正序”重新排布。

### 模式 3：`[🗺️ 纯地图模式]`
- 纯地图沉浸式浏览，点击图钉调出右侧详情抽屉，查看户型图及优缺点。

## 6. 数据持久化机制（LocalStorage + 导入导出）

系统将用户的所有个性化状态持久保存在浏览器 `localStorage` 中：
- 键名 `JIADING_DECISION_USER_WEIGHTS`：保存用户调整的 5 大维度权重；
- 键名 `JIADING_DECISION_CUSTOM_SCORES`：保存用户对特定小区的覆盖评分与看房笔记；
- 键名 `JIADING_DECISION_VETO_ENABLED`：保存高架噪音一票否决开关状态。

在设置面板提供：
- `[💾 导出配置 JSON]`：一键下载包含你所有打分和笔记的备份文件；
- `[📂 导入配置 JSON]`：在其他电脑或手机上一键恢复全部数据。

## 7. Cloudflare Pages 部署与安全密码锁（门禁层）

为了保证部署到公网后的私密性：
1. **密码门禁遮罩层（Access Gate）**：
   - 首次访问时，全屏呈现暗黑毛玻璃安全认证弹窗；
   - 默认访问密码设置为 `6688`（支持进入系统后在设置面板一键修改为自己的私密口令）；
   - 口令通过本地加密 Hash 校验，验证通过后向 `sessionStorage` 写入凭证，解锁主界面；
   - 页面右上角提供 `[🔒 锁定]` 按钮，随时一键退出并重新锁定。
2. **零配置上线 Cloudflare Pages**：
   - 项目纯前端、无服务器端，构建产物即为根目录；
   - 在 Cloudflare Pages 中直接连接 GitHub 仓库，Build Command 留空，Output Directory 设置为根目录，即可全球零成本 CDN 加速访问。

## 8. 现代化多栏联动交互与防遮挡规范 (Interaction Architecture)

针对“分屏模式下右侧侧边抽屉粗暴滑出直接盖死多维表格”的体验缺陷，确立以下交互设计准则：

1. **单选态（Focus & Fly）与深度展开态（Detail Modal）严格解耦**：
   - **单击表格行或地图图钉**：仅执行“视图联动”（高亮当前数据行、地图平滑飞渡至定位点并展开微气泡），**绝不自动弹窗遮盖表格**，确保用户在分屏模式下保持双栏视线通透；
   - **双击表格行或点击操作列【🔍 全景档案】**：唤起 **【居中沉浸式决策工作台弹窗】（Center Workspace Modal）**；
2. **居中工作台模态卡片规范（Center Modal）**：
   - 宽度固定为 880px（最大 94vw），垂直居中，采用毛玻璃暗色背景遮罩；
   - 顶栏固定展示：小区全名、综合推荐得分、所属大盘及板块徽章；
   - 提供 `[◀ 上一个]` 与 `[下一个 ▶]` 快速切换控件，并绑定键盘 `ArrowLeft` / `ArrowRight`，支持用户在弹窗内连续对比不同小区的户型与噪音；
   - 按键盘 `ESC` 或点击外侧遮罩无感退出，瞬时回归原分屏视图，表格滚动位置 100% 保持不变。

## 9. 房产户型图与多模态数据真值血缘治理体系 (Data Lineage & Truth Governance)

针对房产数据采集中“盲目按名字或轮换池分配，导致保利阳光苑等小区三房户型误挂两房图片”的严重失职，建立全链路数据血缘追溯与硬断言防错机制：

1. **权威真值元数据库（Ground Truth Metadata Registry）**：
   - 每一张户型图图片必须依托实测 OCR 与空间房间标尺识别，生成独立真值档案 `data/floorplan_catalog.json`；
   - 记录其物理级属性：`bedroom_count`（真实卧室数）、`rooms_layout`（几室几厅几卫）、实测房间名称与套内面积总和；
2. **编译时硬断言熔断机制（Strict Compile Assertions）**：
   - 在 `scripts/refine_layouts_data.py` 与 `scripts/build_dataset.py` 编译流水线中植入自动化断言：
     - 凡标记为【两房】的户型，其引用的图片在真值库中 `bedroom_count` 必须严格等于 2；
     - 凡标记为【三房】的户型，其引用的图片在真值库中 `bedroom_count` 必须严格等于 3（必须实测含卧室A、B、C）；
     - 凡标记为【改善四房】的户型，其引用的图片必须严格等于 4；
   - 一旦发生任何交叉错挂，编译器直接抛出 `AssertionError` 中断退出，绝不允许任何图文不符的错误数据流入生产运行包！
3. **举一反三与后续扩展规范**：
   - 未来无论是新增嘉定老城、南翔、安亭还是全上海其他区域的小区，在引入新户型图片时，必须先经过 `build_floorplan_catalog.py` 物理定性，方可挂载到小区档案，彻底绝缘经验主义与人工盲配。
